# Vlad Landing System — Design System

## 1. Принцип

Система предназначена для коммерческих лендингов и небольших сайтов, где дизайн должен усиливать понятность оффера и конверсию, а не конкурировать с содержанием.

Визуальный характер по умолчанию: современный, чистый, уверенный, с крупной типографикой, хорошим воздухом и умеренной выразительностью.

## 2. Сетка

- Максимальная ширина контента: `1200px`.
- Горизонтальные поля desktop: `32px`.
- Tablet: `24px`.
- Mobile: `16px`.
- Основная сетка: 12 колонок на desktop, 6 на tablet, 4 на mobile.
- Текстовые колонки не растягивать на всю ширину контейнера: комфортная ширина основного текста — `620–760px`.

## 3. Вертикальный ритм

Использовать шаг 4/8 px и токены из `styles/tokens.css`.

Ориентиры:

- Между крупными секциями: `80–112px` desktop, `56–72px` mobile.
- Заголовок → подзаголовок: `16–24px`.
- Текст → CTA: `24–32px`.
- Между карточками: `16–24px`.

Не уменьшать отступы только ради того, чтобы «всё влезло в один экран».

## 4. Типографика

### Заголовок первого экрана

- Desktop: `48–64px`.
- Mobile: `34–44px`.
- Межстрочный интервал: `0.98–1.08`.
- Вес: `650–800`.

### H2

- Desktop: `36–48px`.
- Mobile: `28–36px`.
- Межстрочный интервал: `1.05–1.15`.

### H3

- `22–28px`.

### Основной текст

- Desktop: `17–20px`.
- Mobile: `16–18px`.
- Межстрочный интервал: `1.45–1.65`.

### Мелкий текст

Не использовать меньше `14px`, кроме юридических примечаний. Юридический текст — минимум `12px` и с достаточным контрастом.

## 5. Цвета

Система не привязана к одному бренду. Цвета задаются токенами проекта.

Обязательные роли:

- `--color-bg`
- `--color-surface`
- `--color-text`
- `--color-muted`
- `--color-border`
- `--color-primary`
- `--color-primary-hover`
- `--color-on-primary`
- `--color-success`
- `--color-danger`

Правила:

- Один основной акцентный цвет на страницу.
- CTA не должен конкурировать с несколькими равнозначными акцентами.
- Цвет не должен быть единственным способом передать состояние.
- Контраст текста и CTA должен оставаться читаемым на мобильных устройствах.

## 6. Кнопки

### Primary

Используется для главного целевого действия.

- Высота: `52–60px`.
- Padding по горизонтали: `24–32px`.
- Radius: `12–16px`.
- Вес текста: `600–700`.
- Минимальная touch-area: `44px`.

### Secondary

Визуально слабее primary: border / light surface / text button.

На одном экране по возможности один главный CTA.

## 7. Карточки

Карточка используется, только если помогает сгруппировать сущность: преимущество, тариф, этап, отзыв, врача, услугу.

- Radius: `16–24px`.
- Border предпочтительнее тяжёлой тени.
- Shadow — мягкая и умеренная.
- Padding: `20–32px`.
- Внутри карточек сохранять одинаковую вертикальную структуру.

Не превращать каждый текстовый фрагмент в карточку.

## 8. Первый экран

Первый экран должен отвечать максимум за несколько секунд на четыре вопроса:

1. Что предлагается?
2. Для кого / в каком контексте?
3. Почему это стоит рассмотреть?
4. Что сделать дальше?

Рекомендуемая структура:

- короткий eyebrow / контекст — только если нужен;
- H1;
- поясняющий текст;
- 1–3 доказательных преимущества;
- primary CTA;
- вторичное действие при необходимости;
- изображение / специалист / продукт, если оно усиливает доверие.

Не использовать абстрактный декоративный визуал вместо смыслового изображения в коммерческом Hero.

## 9. Иконки

- Базовый набор: Lucide.
- Один визуальный стиль иконок на странице.
- Размер обычно `20–24px`.
- Не использовать иконку, если она не помогает быстрее понять содержание.

## 10. Изображения

- Люди должны выглядеть естественно и релевантно услуге.
- Для медицинских проектов предпочтительны реальные врачи/специалисты, если фото доступны.
- Не растягивать изображения с потерей пропорций.
- Использовать `object-fit: cover` только там, где обрезка безопасна.
- По возможности задавать `aspect-ratio`, чтобы не было layout shift.

## 11. Анимация

Допустима для:

- мягкого появления;
- изменения состояния кнопки/карточки;
- раскрытия FAQ;
- карусели/слайдера при реальной необходимости;
- демонстрации процесса или взаимодействия.

Не использовать движение просто для ощущения «дорогого сайта».

Уважать `prefers-reduced-motion`.

## 12. Mobile-first проверки

Перед выдачей блока обязательно проверить:

- H1 не создаёт одиночных коротких строк без необходимости;
- CTA удобно нажимать большим пальцем;
- карточки не становятся чрезмерно высокими;
- нет горизонтального скролла;
- формы имеют крупные поля;
- изображения не выталкивают оффер ниже первого экрана без причины;
- важный текст читается без zoom.

## 13. Accessibility

- Семантические заголовки по уровням.
- `label` для полей формы.
- `alt` для смысловых изображений.
- Видимый `focus`.
- Интерактивные элементы должны работать с клавиатуры.
- Не делать кликабельный `div`, если подходит `button` или `a`.

## 14. Что не использовать по умолчанию

- несколько градиентов в одной секции;
- неоновые обводки;
- чрезмерный glassmorphism;
- бессмысленные 3D-сферы и абстракции;
- автопрокрутку контента, который пользователь должен успеть прочитать;
- чрезмерно маленькие подписи;
- больше двух шрифтов;
- уникальный стиль каждой секции.

## 15. Источники компонентов

Открытые библиотеки могут использоваться как источник паттернов. Приоритетный источник — HyperUI. Любой взятый компонент должен быть приведён к токенам и правилам этой системы перед использованием.

# Tilda Rules

## Общий принцип

Код должен вставляться в HTML-блок Tilda и работать максимально автономно. Предпочтение: нативные HTML/CSS/JS без тяжёлых фреймворков.

## Изоляция стилей

Каждый самостоятельный блок получает уникальный корневой класс, например:

```html
<section class="vls-hero-procto">...</section>
```

Все CSS-селекторы должны начинаться с этого класса или с системного префикса `.vls-`, чтобы не ломать стандартные стили Tilda и соседние блоки.

Не использовать глобальные правила вроде:

```css
h1 { ... }
a { ... }
.container { ... }
```

если они не изолированы внутри блока.

## CSS

- Использовать CSS custom properties для цветов и размеров проекта.
- Не дублировать одинаковые media queries без необходимости.
- Не использовать `!important`, если можно решить специфичностью.
- Учитывать desktop, tablet и mobile.
- Минимальная контрольная ширина mobile: 320px.
- Не задавать фиксированную высоту секции, если контент может меняться.

## JavaScript

- Нативный JS предпочтительнее библиотек.
- Не использовать `document.querySelector` по слишком общим селекторам.
- Инициализировать скрипт после появления DOM.
- Один блок не должен менять элементы соседнего блока.
- Для нескольких одинаковых блоков на странице код должен работать через `querySelectorAll` и локальный root.

## Ссылки и действия

Tilda popup:

```html
<a href="#popup:call">Записаться</a>
```

Телефон:

```html
<a href="tel:+70000000000">+7 (000) 000-00-00</a>
```

Email:

```html
<a href="mailto:example@example.com">example@example.com</a>
```

Для внешних ссылок, открываемых в новой вкладке, добавлять `rel="noopener noreferrer"`.

## Изображения

- Использовать абсолютные HTTPS URL, если изображения лежат на CDN Tilda.
- Всегда задавать `alt` для смысловых изображений.
- Для изображений врача/лица не применять агрессивный `object-position`, который может обрезать голову или лицо.
- Использовать `loading="lazy"` ниже первого экрана.
- Hero-изображение не делать lazy, если оно критично для первого экрана.

## Формы

Если используется нативная форма Tilda, не подменять её JS-логику без отдельной задачи.

Если создаётся собственная HTML-форма, заранее определить, куда уходят данные. Не имитировать отправку формы без реального обработчика.

## Responsive

Контрольные диапазоны:

- `1200px+` — desktop wide;
- `768–1199px` — tablet / small desktop;
- `0–767px` — mobile.

При необходимости добавлять отдельную проверку `480px`.

## Производительность

- Не подключать Tailwind CDN на продакшен-странице только ради одного блока.
- Итоговый Tilda-код желательно отдавать обычным CSS, даже если прототип собирался по Tailwind-паттерну.
- Не подключать иконочную библиотеку, если нужны 1–2 простые иконки — можно использовать inline SVG.
- Не вставлять тяжёлую анимационную библиотеку для простого fade/accordion.

## Совместимость

Перед выдачей убедиться:

- код не зависит от npm/build step;
- отсутствуют JSX/React-конструкции;
- нет относительных путей к локальным ассетам;
- CSS не ломает стандартные `.t-*` классы;
- popup-ссылки сохраняются в формате Tilda;
- телефон и другие действия кликабельны на мобильном.

## Формат выдачи пользователю

Если пользователь просит код «по блокам», выдавать каждый Tilda-блок отдельно и не объединять разные секции в один огромный фрагмент без причины.

Если существующий код меняется, сохранять рабочие ссылки, идентификаторы, тексты и интеграции, если пользователь не попросил изменить их.
